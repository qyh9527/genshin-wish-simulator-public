## 环境与安装

1. 读取[依赖核验](dependencies.md)确定兼容组合：Vite＋TypeScript＋React＋Ant Design及配套图标，内联插件、pure-rand、Vitest与单Chromium Playwright；具体版本只在依赖文档与实际锁文件查询。检查`node --version`、`npm --version`。本轮实际环境为Node v24.20.0、npm 12.0.2；应用运行端无需Node。
2. 首次实施创建package.json并安装选定依赖，生成锁文件；之后使用`npm ci`复现，不无锁安装最新版。保留用户环境的依赖安装脚本权限政策，不擅自放开生命周期脚本。
3. 开发预览使用现有的`npm run dev`，只用于开发交互；正式离线验收必须打开file://产物。

不把此文档当成已执行安装记录；最终版本与引擎要求由package.json和锁文件查询。

## 单文件构建约束

- 以Vite配合经核验的单文件插件内联JS/CSS，资源使用相对基路径；禁止运行时CDN、网络字体、数据请求及独立动态chunk。
- Worker使用Vite官方支持的内联方式（`?worker&inline`），保持默认`worker.format: 'iife'`；不改为`es`。临时验证工程中`es`虽内联成功但file://启动失败，详见[依赖证据](dependencies.md#worker本项目最关键的打包风险)。不能假设HTML内联插件会自动合并独立Worker。Worker不依赖远程import或邻接磁盘文件，运行结束回收资源。
- 生产HTML中的模块形式与file://限制以最小骨架实际验证；若需输出普通内联脚本或由插件适配，检查转换后不残留跨文件import。开发服务器成功不视为通过。
- 发行内置名单、概率模型与版本说明，脱离源码、依赖目录仍能运行；产物不包含玩家数据、凭据或本机绝对路径。
- 构建只管理已知自产文件；不得递归清空未知release内容。首次存在同名产物时先检查目标，按已有授权边界确认覆盖；构建配置避免默认清空整个发行目录。

## 命令接口

| 命令 | 预期职责 | 通过条件 |
| --- | --- | --- |
| `npm run typecheck` | TypeScript不发射类型检查 | 退出0，无类型错误 |
| `npm test` | 单次运行纯引擎/统计测试，不进入watch | 记录通过/失败数量，无未说明失败 |
| `npm run build` | 类型检查后生产打包并输出中文单HTML | 精确目标存在，构建退出0 |
| `npm run test:e2e` | Playwright实际file://桌面/手机交互 | Worker可用、无必需网络请求、核心交互通过 |
| `npm run bench` | 固定参考场景真实百万次测量 | 记录完整试验数、耗时与环境；阈值失败如实报告 |

测试、构建输出较大时保存在系统临时目录，本地提取计数和第一处完整错误；不把全日志放进上下文或正式发行目录。相关实现及接线完成后集中验证，最小离线骨架例外。

## 离线验收步骤

1. 检查发行目录：HTML本身包含所有运行依赖；没有必须的assets/JS/CSS邻接文件。扫描网络URL时区分可点击来源链接与会触发加载的资源，不能误删来源说明。
2. 使用真实浏览器打开目标文件的file://URL；阻断HTTP/HTTPS请求，确认无外部资源依赖；data:/blob:资源允许。监听console、pageerror与Worker错误。
3. 操作手动抽卡、目标队列、保底输入、星辉回投；运行百万次任务并取消、重启，记录完成次数与结果；不以仅渲染页面替代交互验收。
4. 在约1440px与390px视口截图并亲看，核对数字、表单、滚动和触屏交互；性能记录与截图证据从入口文档可达。
5. 将HTML复制到独立临时目录，仅凭这一个文件重复关键交互，证明不隐式依赖src或node_modules。

## 更新与回滚

7.2更新先核验[规则与证据](rules.md)规定的官方名单和文本变化，再修改内置快照与版本标识，集中复验受影响部分并重新构建。离线文件不会自行联网更新。

回滚使用已核验的旧发行文件或本地Git中的源码与锁文件重建；旧产物保留版本标识，不能改文件名后伪装成新规则。发布/上传/推送不在本轮授权范围，本地构建不等于已发布。
