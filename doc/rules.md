## 结论与证据等级

已直接读取官方当前活动池JSON，确认基础概率、硬保底、大小保底、星辉和当前名单；官方公告确认5.0起武器定轨1点。软保底属于社区推断，捕获明光完整算法仍未公开。工具应称“基于公示规则与社区模型的模拟”，不能承诺完全复刻真实服务端。

官方来源定义确定规则；社区原始分析/源码定义可复核的估计；产品近似定义为了减少输入而作的假设。三层分别展示。搜索摘要只是入口，不作为已验证参数。

### 武器定轨

官方公告原文：“the number of Fate Points needed for Epitome Invocation has been adjusted to 1”；[中文官方说明](https://www.miyoushe.com/ys/article/56646662)正文同样明确“命定值上限将从2降低为1”，已通过Exa读取。当前详情确认非定轨五星得命定值；已满下一金必定轨；抽到定轨武器或更换/取消定轨、卡池结束时清零。五星垫抽、UP保底与命定值独立。

无UP保底且0命定值：定轨37.5%、另一UP37.5%、常驻25%；有UP保底且0命定值：两UP各50%；命定值1：定轨100%。定轨命中后清命定值并清五星UP保底。两种UP武器都按身份计数。

官方严格上界仍为160抽获取定轨武器；下述社区曲线会提前到77抽必金，因此模拟中的模型上界为154，不把154宣传成官方硬保底。

## 社区逐抽模型

采用[OneBST/GGanalysis原始模型源码](https://github.com/OneBST/GGanalysis/blob/5b146921c2844291548bf5621eb0d7ca79223d64/GGanalysis/games/genshin_impact/gacha_model.py)，固定提交5b146921c2844291548bf5621eb0d7ca79223d64，文件最近提交2026-01-30。[KQM实测记录](https://library.keqingmains.com/evidence/general-mechanics/gacha)独立支持角色74、武器63开始软保底。模型源码为原始实现证据，不等于官方实现。

令n=距上次相应稀有度后本次序号：

| 概率表 | 分段 |
| --- | --- |
| 角色五星p5(n) | 1—73：0.006；74—89：min(1,0.006+0.06×(n−73))；90：1 |
| 武器五星p5(n) | 1—62：0.007；63—76：0.007+0.07×(n−62)；77及以后：1 |
| 角色四星q4(n) | 1—8：0.051；9：0.561；10及以后：1 |
| 武器四星q4(n) | 1—7：0.06；8：0.66；9及以后：1 |

原始源码对四星主动注明忽略五星挤占，本项目补建明确的联合模型：先以p5判五星；p5=1时直接出五星，不执行除法；未出五星时以min(q4,1−p5)/(1−p5)判四星。非保证段保持四星无条件概率q4，概率质量冲突时先给五星，剩余全部给四星。五星出现时四星计数+1且不重置；四星出现时四星计数归零。该联合处理是产品模型，不能归因于原始源码已经完整实现。

[Hu Tao计算器说明](https://hutaobot.moe/tools/gachacalc)与[Wiki注释](https://genshin-impact.fandom.com/wiki/Wish#Notes)支持五星挤占后四星递延；其精确竞争概率未被官方披露。需要对联合模型实际长程四星频率作测量，不能直接套用忽略五星时的13%/14.5%。

本轮使用生存概率解析求和而非抽样：角色五星平均间隔62.297332抽、综合1.605205%；武器53.250391抽、综合1.877920%。这是所选曲线数学结果，不是当前游戏实测；与公示1.6%/1.85%的差异保留，不为强行对齐而无证据改参数。

## 捕获明光：确定与不确定

官方当前详情与2025-02-10公告均确认：基础概率0.018%；含明光综合55%；连续三次都到第二个五星才获取UP后，下次五星保证触发。官方未给完整隐藏计数与概率曲线，不能据此推出每次小保底独立55%，也不能把0.018%直接作为每次出金的明光率。

### 首版默认：保守计数器模型

modelId建议`community-counter-conservative-v1`。采用上述固定源码的CR_P=[0,0,0,1]，CR_P是明光触发概率而非最终UP率；作者明确说明该模型不完全、会高估所需抽数。[作者原始研究](https://www.bilibili.com/video/BV13XBiYZErT/)标题“用400万抽拆解捕获明光系统，比公示的更复杂”；已读取作者简介，未把未读取的视频内容当作额外参数证据。

| 隐藏计数c | 明光率r | 非大保底最终UP率 | 转移 |
| --- | --- | --- | --- |
| 0 | 0 | 50% | 普通赢留0；歪后到1 |
| 1 | 0 | 50% | 普通赢到0；歪后到2 |
| 2 | 0 | 50% | 普通赢到1；歪后到3 |
| 3 | 1 | 100% | 明光命中后到1 |

歪后下一次大保底UP不再改变计数；默认初始c=1是模型初始化，不代表用户当前账号的已知历史；允许高级输入0—3。大保底且c=0在此模型不可达，需校验。UI须显著标“捕获明光：保守社区模型，可能低估达成率”，不显示为已经完全核实的真实机制。

解析稳态：上述模型非大保底UP率6/11≈54.545455%，全部五星含大保底UP份额11/16=68.75%。两者分母不同，均不能写成“每次五星55%限定”。

### 不采用的推断

[radiance项目](https://github.com/VanheXen/radiance/blob/main/README.md)与[Hu Tao](https://hutaobot.moe/tools/gachacalc)提到状态2约54.5%/55%最终UP，但前者README又把54.5%称为明光概率，存在分母表述冲突。原始Reddit研究链接本轮Exa不可用、直接HTTP403，不能声称已读原始分析。常见50/50/75/100模型也未获得足够原始证据。

为了使上述计数模型长程接近55%，可数学拟合状态2明光率约9%，但这不是游戏证据，首版不据此改参数。后续有更强原始证据时升级 modelId，并重新核验影响。当前默认只作可复核的保守估计，不声称0.018%极罕见分支已经精确复现。

## 四星产品近似

账号初始化按[产品契约](product.md)生成固定快照。当前官方详情给出四星角色/武器的基础总率各占一半，但没有完整披露非UP类别权重与历史平稳算法。首版显式采用：先判UP保证/UP分支；非UP时角色/武器各50%，在对应非UP合格身份中均匀抽取；排除当期UP，非UP分支不重复抽到UP。两个角色池共用同三名UP四星；武器池抽到这些角色仍更新同一份持有状态。

这项近似与GGanalysis源码“未考虑UP从常驻分支获取、未考虑平稳机制”的警告保持一致，但不是官方已确认的精确分类算法。展示结果时列出“软保底、明光、非UP四星分类及初始命座为模型/近似”；百万次只减少采样误差，不能消除它们。
